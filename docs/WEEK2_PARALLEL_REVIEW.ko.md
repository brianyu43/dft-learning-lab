# 2주차 코어 수 재검토

2026-09-10. 사용자가 18코어 Mac에서 ORCA를 1코어로 실행한 점을 지적하고 적절한 코어 수를 물었다. 첫 기준을 직렬로 잡은 선택은 하드웨어 활용 면에서 지나치게 보수적이었다. 기존 계산을 보존하고 프로젝트 전용 MPI 환경과 비교 실행을 준비한다.

실제 `sysctl` 확인 결과 Super 6코어, Performance 12코어, 물리/논리 코어 각각 18개, RAM 64 GiB다. 최초 권장값은 12 MPI 프로세스이며, 실행 가능한 최적값으로 확정한 것은 아니다. 이번 ORCA 배포판 이름이 `openmpi411`이고 동적 라이브러리가 `libmpi.40.dylib`를 요구하는 것을 확인해 별도 `.tools/orca-mpi` 폴더에 OpenMPI 4.1.1을 설치했다. 전역 설정과 진행 중 프로세스의 환경은 변경하지 않았다. 정확한 패키지는 `environment/orca-mpi-explicit.txt`에 남긴다.

MPI 최초 기본 실행은 30초 제한에 걸렸다. 로컬 인터페이스를 명시한 재점검은 12.74초, 이후 반복은 0.29초에 종료했고, 기본 설정 반복도 0.29초에 통과했다. 최초 기동 지연의 정확한 시스템 원인은 확정하지 않았다. 이는 화학 엔진 정확성 검증과 별개인 실행기 점검이다.

진행 중인 2주차 핵심 계산을 먼저 마친 뒤 다음 비교를 순차 실행한다.

1. 기존 물 구조로 2프로세스 Opt/Freq를 실행해 MPI 엔진을 확인한다. 1주차 직렬 결과와 에너지 1e-6 Hartree, 진동수 0.1 cm⁻¹ 이내인지 확인한다.
2. 검증된 50원자 디플루니살–카페인 좌표를 고정하고 `r2SCAN-3c TightSCF EnGrad`를 1·8·12·16프로세스로 실행한다. 순서는 첫 반복 1→8→12→16, 두 번째 반복 16→12→8→1이다. 각 실행은 새 초기 추정에서 시작한다.
3. 기준 대비 에너지 차이 1e-6 Hartree 이하, 원자별 기울기 차이 벡터 크기의 최대값 1e-5 Hartree/Bohr 이하를 확인한다. 이 수치는 이번 비교의 운영 기준이다.
4. 각 설정의 두 실행 중앙 시간과 메모리를 보고 가장 빠르게 관측된 설정을 고른다. 두 반복으로 열·OS 변동이 완전히 통제되지는 않는다. 이합체 전체 최적화 반복 수나 분석적 Hessian의 가속률로 일반화하지 않는다.

추가 비교는 최대 45분 검토 예산, 작업별 최대 15분, 프로세스 트리 RSS 40 GiB, 자동 재시도 없음이다. ORCA 드라이버 자체는 `mpirun`으로 시작하지 않고 입력의 `%pal nprocs N end`로 병렬 모듈을 요청한다. MPI 프로세스마다 BLAS/OpenMP는 1스레드로 제한한다.

실행 프로그램: `scripts/run_week2_parallel_benchmark.py --execute`. 기본 핵심 파이프라인이 끝나기 전에는 이 스크립트가 실행을 거부한다. 이 비교는 후속 전체 약물 대조군이나 3주차 계산을 시작하지 않는다.

근거: [ORCA 병렬 실행 문서](https://www.faccts.de/docs/orca/6.1/manual/contents/essentialelements/parallel.html). RI-DFT에서 대략 16프로세스까지를 검토할 만하다는 문서 설명과 실제 CPU 구성을 바탕으로 비교 범위를 정했다.
