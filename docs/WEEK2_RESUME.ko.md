# 2주차 재개 기록

2026-09-11 사용자의 “계속하자” 요청으로 재개했다. 중단 시점 목록의 28개 파일 해시를 먼저 확인했고, 변경할 문서·스크립트의 당시 바이트는 `runs/week2-resume-20260911/pause_snapshot`에 보존했다. 원래 이합체 로그와 최적화 좌표·GBW는 변경하지 않는다.

## 병렬 환경의 실제 검증

첫 물 2프로세스 실행 `p2-water-n2-r0`는 `orca_startup_mpi`가 `libmpi.40.dylib`를 찾지 못해 7.297초 후 종료됐다. MPI 실행기 자체의 성공만으로 ORCA 병렬 계산이 보장되지 않았음을 확인했다. 해당 출력은 보존했다.

수정된 revision 2 입력은 MPI 및 직접 의존 라이브러리 5개를 실행 폴더에 동봉하고 각 해시를 실행 메타데이터에 기록한다. 전역 라이브러리 경로나 ORCA 배포 바이너리는 수정하지 않았다. 물의 2프로세스 Opt/Freq가 정상 종료했고, 기존 직렬 에너지·진동수와 정해 둔 오차 안에서 일치했다. 이후 저장한 50원자 구조에서 1·8·12·16프로세스 EnGrad를 두 번씩 비교했고 에너지·기울기 일치 검증을 통과했다.

Freq 재개 설정은 12프로세스의 중앙 실행 시간이 가장 빠른 설정의 105% 이내이면 12프로세스를 사용한다. 그보다 차이가 크면 가장 빠르게 관측된 설정을 사용한다. 실제 중앙 시간은 1/8/12/16프로세스 각각 171.177/40.624/37.756/37.574초였다. 12프로세스는 16프로세스보다 약 0.5% 느렸으며, 위 규칙에 따라 12프로세스를 선택했다. 코어 수에 따른 에너지·기울기 일치와 속도 측정은 `reports/week2-parallel-benchmark.json`에 남겼다. 이 선택은 EnGrad 실측에 기반하며 전체 Hessian 가속률을 미리 가정하지 않는다.

## 최적화와 진동을 분리한 검증

원래 이합체의 87회 최적화는 로그에서 수렴했고, 사용자 정지는 그 이후의 진동 적분 단계였다. 새 작업은 동일한 좌표에서 `r2SCAN-3c TightSCF Freq`만 실행한다. 미완성 Hessian을 재활용하거나 최적화를 처음부터 반복하지 않는다.

새 검증기는 다음을 함께 확인한다.

- 원래 최적화 로그·좌표·체크포인트 해시와 수렴 기록.
- 새 입력의 방법·전하·다중도·원자 순서와 복사한 좌표.
- 새 엔진의 정상 종료와 전자 수렴, 150개 전체 모드 중 6개 외부 모드 및 144개 진동의 완전성.
- Hessian 원자 좌표와 원래 최적화 좌표의 일치. ORCA가 좌표 원점이나 방향을 바꿀 수 있으므로 동일 원자 순서의 평행 이동·정회전만 허용하고 1e-7 Å 허용오차를 사용한다.
- 로그와 Hessian 진동수의 일치, 모든 내부 진동의 양수 여부, 최적화 에너지와 새 전자 에너지의 1e-6 Hartree 이내 일치.

원래 중단된 실행은 그대로 중단 이력으로 남고, 새 Freq의 정상 종료를 원래 실행의 정상 종료로 바꾸지 않는다. 동일 구조의 최소점 판정은 두 실행의 증거를 연결해 내린다. 재개 관련 회귀 검사는 실제 물 Hessian을 사용해 좌표 원점 이동 허용, 결합 길이 변조·원자 종류 변조·불완전 주파수 목록의 거부를 확인한다. 기존 검사를 포함해 17개가 통과했다.

## 나머지 범위

재개한 Freq는 실제 1005.252초(16분 45초)에 정상 종료했다. 144개 내부 진동은 모두 양수이며 최저 진동수는 25.795744 cm⁻¹이다. Hessian 좌표와 보존 좌표의 일치, 중원자 연결과 수소 위치 유지도 확인했다. 원래 최적화 에너지와의 차이는 8.4711e-8 Hartree다. 단량체 2개와 이합체 1개의 최소점 검증을 모두 통과했고, 진공 전자 결합 에너지는 -5.419637 kcal/mol이다. 새 Freq의 프로세스 트리 최대 샘플 RSS는 35.203 GiB였다. 원래 중단 실행 156.3436분과 새 Freq 16.7542분은 비용에서 모두 보존한다.

이합체 진동 검증 뒤 기존 16개 MoS₂ 이중층/분리층 SCF 입력을 순차 실행한다. 연구 입력의 cutoff·k-grid·좌표·방법은 유지한다. 새 유한 실행기는 `scripts/finish_week2_resume.py`이며 자동 재시도와 3주차 작업은 없다. 계산 비용은 원래 중단 시간과 재개 시간, 별도 병렬 검증 비용을 구분해 합산한다.
